08 · DEBUG PROMPTS
When AI gets stuck — say one of
these.
AI will get something wrong. That's normal. These prompts unstick 90% of issues.
IF A PAGE WON'T LOAD
I'm getting an error when I visit /play. The terminal shows: [paste full error from terminal here]. Look at the relevant file and fix the root cause. Don't add error swallowing or workarounds — find what's actually broken.
IF THE UI LOOKS WRONG
The [Header / Modal / Card] doesn't match my brand. It should be: 2.5px black borders, 4px hard black drop shadow (no blur), brand colors from src/lib/colors.ts only, no gradients, no soft shadows. Fix it. Show me exactly what changed.
IF AI MADE UP AN API
You used a function/import that doesn't exist. Check the actual Next.js 15 docs and Supabase JS docs before writing code. If you're not 100% sure, ask me to check the docs.
IF TYPES ARE BROKEN
TypeScript is complaining: [paste error]. Don't use 'any'. Fix the actual type — usually by checking what Supabase returns. Look at the relevant table schema and update the types.
IF SOMETHING STOPS WORKING AFTER A PROMPT
After your last change, [feature X] broke. Without rewriting unrelated code, find what your previous edit broke and restore correct behavior.
IF YOU WANT A SMALLER CHANGE
Don't refactor everything. I just want [one specific thing]. Touch the minimum number of files. Show me the diff before applying.
IF AI IS GOING IN CIRCLES
Stop. Read the entire file at [path/to/file.tsx] from top to bottom. Tell me what it does in 3 sentences. Then I'll decide what to change.
THE GIT SAFETY NET
Cursor has built-in version control. After every working feature, run git add . && git commit -m
"working: [feature]" in Cursor's terminal. If AI breaks something, run git reset --hard HEAD to
roll back to the last good state. Commit often. Trust nothing.

11 · GOLDEN RULES
10 things to remember while you
build.
01
Prompt small. Test often.
One prompt = one feature. Don't ask AI to 'build the whole app.' Build it brick by brick, run
npm run dev between each, commit when it works.
02
Commit after every win.
git commit -m 'working: photo upload' is your safety net. AI is occasionally wrong. Git lets you
roll back instantly.
03
Show, don't tell.
Paste screenshots into Cursor's chat. AI sees images. Showing a broken layout is 10× faster
than describing it.
04
Be specific about brand.
Generic prompts get generic UI. Repeat your brand colors, border thickness, and shadow
style in every visual prompt.
05
Use Composer for big changes.
Cmd+I (Composer) edits across multiple files. Use it for full features. Use chat (Cmd+L) for
questions.
06
Read what AI writes.
Don't blindly accept. Skim the code. If you see something weird, ask 'why this approach?'
Don't be polite, be curious.
07
AI lies confidently sometimes.
If a function call looks suspicious, paste it back: 'Does Supabase JS v2 actually have this
method? Check the docs.'
08
Backend last.
Build all UI with mock data first. Only wire to Supabase once the experience feels right.
Switching is fast.
